# Multi-Cluster Perf Summary (2026-04-22)

Environment:
- macOS darwin/arm64
- Apple M1
- package: `github.com/elijahrou/surfsk8s/internal/app`

Raw results:
- baseline: `results/multicluster-perf/2026-04-22-baseline.txt`
- after: `results/multicluster-perf/2026-04-22-after.txt`

Bench intent:
- measure typed resource/detail screens while unrelated pod churn happens across 8 clusters
- capture the invalidation problem where global store version forced expensive refreshes on unrelated screens

Key deltas:
- `BenchmarkTickDeployments8ClustersUnderPodChurn`
  - before: ~219 us/op
  - after: ~1.17 us/op
  - result: ~187x faster
- `BenchmarkTickServices8ClustersUnderPodChurn`
  - before: ~221 us/op
  - after: ~1.17 us/op
  - result: ~188x faster
- `BenchmarkTickNodes8ClustersUnderPodChurn`
  - before: ~27.1 us/op
  - after: ~1.17 us/op
  - result: ~23x faster
- `BenchmarkTickDeploymentDetails8ClustersPodChurn`
  - before: ~1.76 us/op
  - after: ~1.17 us/op
  - result: ~1.5x faster

Changes behind the gain:
- store now tracks per-kind versions
  - pods
  - deployments
  - services
  - nodes
- typed list/detail screens only refresh on relevant kind version changes
- removed global manager-version short-circuit from typed-screen refresh gating

User-visible expectation:
- deployment/service/node pages should stop freezing when pods churn heavily in other clusters
- pod-only churn should not force full deployment/service/node list rebuilds anymore
